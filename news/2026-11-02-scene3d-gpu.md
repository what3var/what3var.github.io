---
title: scene3d draws on the GPU
tag: scene3d
---
The 3D engine of fire can now let the GPU draw: `scene.Renderer = RenderMode.Hardware` renders a scene through Vulkan, and with `camera.DirectDrawing` the pictures go straight into the window. Where there is no GPU, the software renderer draws as before - a program never has to care.

- **In C now.** The renderer is plain C99 like the other standard packages. It draws the same pixels as the C++ renderer did, byte for byte, and just as fast; scene3d programs build with TinyCC too.
- **Vulkan, but optional.** Vulkan is loaded when the hardware renderer is first asked for - Windows, Linux, Android, and macOS through MoltenVK. Building fire or a program needs no Vulkan SDK. No GPU, no driver: `camera.LastRenderer` and `S3D.HardwareError()` say what happened, and the software renderer takes over.
- **The same look.** The GPU draws everything the software renderer does: per-pixel lighting, textures, bump maps, cut-outs, transparency, billboards, layers and soft shadows.
- **No limits on lights and shadows.** Lights and shadow maps live in storage buffers, the shadow maps in an atlas. When there are more maps than memory, they get smaller - a light never loses its shadow. Tried with 250 lights and 1250 shadow maps.
- **DirectDrawing.** The picture is not read back from the GPU: it goes into the window through a swap chain, and `Render` no longer waits for the GPU. What the program draws into the framebuffer after `Render` - a HUD, a UI - is laid over the picture. The new sample *Scene3D Benchmark* compares software, hardware and DirectDrawing on your machine.

Also new: programs with a window build with TinyCC on Linux as well (`--toolchain tcc`). So far the hardware renderer was tried on Linux; Windows, macOS and Wayland are next. See [3D scenes](docs/topics/scene3d.html) in the docs.
